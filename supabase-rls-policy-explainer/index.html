What "leak" means here

  • USING (true) — or a tautology like 1=1 — means every row matches. On a table a client role can reach, that reads (or changes) every row. Fix a permissive policy.
  • No WITH CHECK on INSERT/UPDATE — the new row isn't constrained, so a client can write a row as another user. The correct owner-scoped set.
  • anon with no auth.uid() scope — signed-out visitors read whatever the predicate allows. Fine for a public catalog; a leak for anything private.
  • UPDATE with an open USING — even if WITH CHECK is scoped, an open USING lets any row be targeted. Both matter.
